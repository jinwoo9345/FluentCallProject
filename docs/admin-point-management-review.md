# 포인트·결제·관리자 변경 및 배포 체크리스트

## 반영 내용

- 추천인 등록 여부와 관계없이 보유 포인트를 기본 자동 적용. 사용자가 해제 가능하며 가격을 초과한 잔액은 보존.
- 전액 포인트 결제는 PG/입금 없이 서버 트랜잭션에서 완료. 부분 사용은 서버 가격에서 포인트를 뺀 금액만 결제.
- 본인 잔액이 비정상이면 사용 불가/관리자 문의 안내 후 포인트 없이 정가 결제 가능. 원본 잔액은 임의로 초기화하지 않음.
- 추천인 잔액이 비정상이거나 보상 지급 후 안전한 정수 범위를 초과해도 결제 완료는 유지. 보상만 관리자 확인 대상으로 기록하고 결제 관리의 재확인 버튼으로 문제 해결 후 한 번만 지급.
- 주문 생성·선물·승인·취소·보상·반환을 서버로 이동. Firebase ID 토큰 검증, 신규 이메일 계정 인증 제한, 주문 소유자·금액 검증.
- 일반 사용자의 직접 잔액 변경, 결제/선물/원장 위조를 Firestore 규칙에서 차단. 신규 서버 주문의 금전성 필드는 관리자 클라이언트도 직접 수정 불가.
- 주문/선물 요청 번호를 재사용해 응답 유실 재시도와 중복 클릭으로 재차감하지 않음. 반환·추천 보상도 주문 상태와 원자적으로 한 번만 처리.
- 카드 결제는 토스 실제 상태가 DONE이면 완료, 실패/만료가 확인되면 포인트 반환. 조회 장애·승인 진행 중에는 임의 반환하지 않고 재확인 상태 유지.
- 로그인·화면 복귀·5분 주기·결제 화면에서 미완료 신규 카드 주문 재확인. 아직 진행 가능한 pending 주문은 건드리지 않으며 45분 지난 주문부터 만료 여부 확인.
- 토스 웹훅 수신 경로 `/api/payments/webhook` 추가. 요청 본문 상태는 신뢰하지 않고 서버 키로 토스를 조회 후 처리.
- 사용/반환/보상은 `point_ledger`, 선물은 `point_transfers`, 관리자 조정은 `point_adjustments`에 기록. 잔액과 기록은 함께 저장/롤백.
- 전체 사용자 회수 및 사용자 잔액 초기화 제거. 사용자별 양의 정수 지급/회수, 사유·확인, 잔액 초과 회수 거부.
- 관리자 포인트 내역 페이지: 6종 내역, 사용자·기간·검색·유형 필터, 전후 잔액, 처리자·사유·주문번호 표시. 서버 주문에서 결제 파생 로그를 중복 생성하지 않음.
- 관리자 메뉴를 현황/운영/회원·강사/결제·포인트/설정 그룹으로 분리. URL `?tab=`으로 현재 위치 유지.
- 승인/취소 확인 중인 주문도 관리자 처리 대기에 포함. 카드 주문에 수동 입금 승인 버튼을 제공하지 않음.
- 취소/실패 무통장 주문 재시도 시 입금 안내 차단. 이전 요청 번호를 해제하고 사용자가 다음 신청을 누르면 새 주문 생성. 승인/취소 확인 중에는 기존 주문 상태 확인만 안내.
- 데이터 조회 실패를 경고로 노출하고 설정 조회 실패 시 빈 설정 저장 차단.
- 강사 승인·직접 등록·거절의 Firestore 문서 변경을 트랜잭션으로 처리. 관리자 역할 변경과 기존 강사 프로필 덮어쓰기를 방지.
- 처리된 강사 신청의 삭제를 막아 승인/거절 이력을 보존. 대기 신청 삭제와 해당 신청자 상태 정리도 트랜잭션으로 처리.

## 기존 데이터

과거 누락 반환이나 이력을 소급 수정하지 않는다. 자동 복구는 `flowVersion: 2` 신규 주문만 대상으로 한다.
기존 입금 대기 주문은 기존 관리자 승인/취소 기능을 유지한다. 완료 주문의 실제 결제 취소/현금 환불은 이번 기능에 포함되지 않는다.
과거 로그의 미기록 수령인·시각·잔액은 추정하지 않고 미기록으로 표시한다.

## 운영 반영 전 필수 확인

1. Cloudflare Pages **서버** 환경 변수: `FIREBASE_PROJECT_ID`, `FIREBASE_API_KEY`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`, `FIREBASE_DATABASE_ID`, `TOSS_SECRET_KEY`.
   서비스 계정에는 해당 Firestore DB 읽기/쓰기 권한이 필요하다. 서버 시크릿에 `VITE_` 접두사를 붙이지 않는다.
2. `FIREBASE_DATABASE_ID`는 브라우저의 `VITE_FIREBASE_DATABASE_ID`와 반드시 일치해야 한다. 미설정 시 코드는 기존처럼 `(default)`를 사용한다.
   `firebase.json`의 규칙 배포 대상은 `ai-studio-d88729c3-7ce8-4749-a34f-6b30f0d26163`이다. 실제 운영 DB와 일치 여부를 확인한다.
3. 신규 서버 API·프런트엔드·Firestore 규칙을 같은 릴리스로 배포한다. 이전 브라우저/클라이언트는 직접 결제·선물 쓰기가 거부되므로 새로고침 안내가 필요하다.
   Cloudflare와 GitHub Actions는 별도 배포이므로 완료 시점이 자동으로 일치하지 않는다. 운영 저사용 시간에 진행하고 두 배포 모두 성공했는지 확인한다.
4. GitHub Actions `Deploy Firebase Rules`는 main의 규칙/설정 변경을 감지해 배포한다. `FIREBASE_TOKEN` Secret이 유효해야 한다.
   2026-09-09 최근 실행 성공을 확인했다: https://github.com/jinwoo9345/FluentCallProject/actions/runs/34355451554
   이번 변경의 푸시 후에는 신규 워크플로 실행 결과를 확인해야 한다. 과거 실행 성공이 이번 배포 성공을 보장하지 않는다.
5. 토스 개발자센터에서 결제 상태 변경 웹훅을 `https://운영도메인/api/payments/webhook`으로 등록한다.
   서버 코드만 추가하면 토스가 자동으로 웹훅을 보내는 것은 아니다. 미등록 시 사용자 재방문 시 복구는 가능하지만, 사용자 부재 중 즉시 복구는 보장하지 않는다.
6. 테스트 키/운영 키의 짝, 은행 계좌 설정, 인증 회원의 부분/전액 포인트 결제·선물·관리자 조정·실패 복구를 운영 또는 전용 테스트 환경에서 확인한다.

## 검증

- `npm test`: 잔액 계산·6종 이력·필터·자동 적용·서버 가격·소유자 확인·이체·중복 요청·취소 반환·보상·PG 장애·만료 복구·인증 실패.
- `npm run test:rules`: 운영과 분리된 `demo-point-audit` 로컬 Firestore 에뮬레이터. 관리자 로그 원자성·읽기 제한·변조 금지·일반 사용자 잔액/주문 위조 차단·기존 프로필/주문 호환.
- `npm run test:money-rest`: 같은 로컬 에뮬레이터에서 실제 Firestore REST beginTransaction/batchGet/commit/query를 사용해 결제·반환·보상·이체와 재시도 검증.
- `npm run lint`, `npm run build`: 타입 검사 및 빌드. 로컬 브라우저용 Firebase 값은 더미 설정을 사용하며 운영 로그인/실결제 성공을 의미하지 않는다.

## 후속 개선

- 기록량이 증가하면 관리자 전체 컬렉션 조회를 날짜 범위·서버 cursor 페이지 조회로 전환. 현재 화면 페이지 분할은 읽기 비용 자체를 줄이지 않는다.
- 강사 Auth custom claim은 Firestore와 별도 서비스여서 원자적 변경이 불가능하다. 실패 안내와 강사 권한 동기화 재시도를 제공한다.
- 완료 주문의 실제 PG 환불, 포인트/추천 보상 회수 정책은 별도 환불 업무로 설계해야 한다.
