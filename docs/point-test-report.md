# 포인트 전용 검증 결과 (2026-10-13)

운영 데이터와 실제 토스 API는 사용하지 않았다. Firestore 저장·트랜잭션·규칙 검증은 `demo-point-audit` 로컬 에뮬레이터에서 수행했다.

## 실행 결과

- `npm run test:points`: 정상 동작 검증 41개 통과, 토스 관련 6개 제외.
- `npm run test:rules`: 보안 규칙 검증 12개 통과.
- 총 53개 정상 동작 검사 통과. 추천인 비정상 잔액 재현 검사는 보완된 동작을 확인하는 회귀 검사로 전환했다.
- 타입 검사·빌드·`git diff --check` 통과. 빌드에는 기존 대용량 번들 경고가 있다.

## 확인 범위

- 수강권 3종 × 잔액 0/부분/전액/초과 × 추천인 유무 × 포인트 사용/미사용 = 48가지 조합.
- 자동 적용, 초과 잔액 보존, 전액 포인트 주문 완료, 무통장 대기 주문 취소와 반환.
- 중복 주문·선물·취소·보상, 승인/취소 동시 요청, 부족/소수/과도한 선물 금액 거부.
- 실제 REST 트랜잭션으로 동시 주문 시 포인트 전액 중복 사용 금지와 추천 보상 한 번만 반영 확인.
- 사용자별 관리자 지급/회수 로그, 원자적 저장·롤백, 일반 회원 잔액/주문/원장 위조 차단.
- 포인트 이력 유형/검색/사용자/날짜 필터와 신규 주문 이력 중복 제거.

## 비정상 포인트 잔액 보완

초기 검사에서는 추천인의 비정상 `credits` 때문에 입금 승인까지 롤백되는 문제를 확인했다. 후속 수정으로 다음 동작을 검증했다.

- 본인 잔액이 음수·소수·문자열·비유한 수·안전한 정수 범위 초과이면 포인트를 사용하지 않고 정가 주문을 생성한다. 결제창에 사용 불가/관리자 문의 안내를 표시하며 원본 잔액은 변경하지 않는다.
- 추천인 잔액이 비정상이거나 보상 지급 후 안전한 정수 범위를 초과하면 결제는 완료하고 보상만 `needs_review`로 기록한다. 정상인 결제자의 포인트 사용에는 영향을 주지 않는다.
- 관리자 재확인 전에는 지급 로그를 만들지 않는다. 잔액 문제 해결 후 재확인하면 고정된 보상 대상에게 한 번만 지급한다. 중복·동시 재확인도 중복 지급하지 않는다.
- 포인트를 사용하지 않은 주문 취소는 비정상 잔액을 그대로 유지하며 완료된다.
- 메모리 기반 회귀 검사와 실제 Firestore REST 트랜잭션으로 비정상 본인/추천인 잔액, 정가 주문·취소·입금 승인·보상 재확인을 검증했다.

취소된 무통장 주문 재시도 시 잘못된 입금 안내 문제는 아래 추가 보완으로 수정했다.
관리자 로그인 기반 UI 통합 시험, 실제 운영 환경 변수/서비스 계정 권한 확인은 이번 로컬 검증에 포함되지 않는다.

## 무통장 취소 안내 추가 보완 (2026-10-13)

- 결제수단 탭이 아니라 서버가 반환한 주문 상태/결제수단으로 다음 화면을 결정한다.
- 실제 `pending` 무통장 주문에만 입금 안내를 제공한다.
- 취소/실패 주문은 입금을 금지하는 안내를 표시하고 이전 요청 번호를 해제한다. 다음 신청 클릭은 새 주문을 생성하며 자동 재신청하지 않는다.
- 승인/취소 확인 중이거나 상태/수단이 불명확하면 같은 주문 확인 안내만 제공한다. 자동 취소·입금 안내·중복 주문 생성은 하지 않는다.
- 상태 분기 테스트 5개와 취소→동일 주문 재시도→새 주문 신청 회귀 테스트 1개를 추가했다.
- 상태 분기 및 취소 회귀 검사도 위의 최신 통과 건수에 포함된다.

## 재실행

로컬 Firestore 에뮬레이터(127.0.0.1:8089, 프로젝트 demo-point-audit, firestore.rules)를 실행한 뒤:

```sh
npm run test:points
npm run test:rules
npm run lint
```

포인트 전용 명령은 `POINTS_ONLY=1`로 카드 승인/웹훅 등 토스 관련 테스트를 명시적으로 건너뛴다.
테스트는 운영 데이터를 변경하지 않았다. 커밋·푸시 후에도 실제 운영 결제와 서버 환경 변수 검증은 별도 확인이 필요하다.
